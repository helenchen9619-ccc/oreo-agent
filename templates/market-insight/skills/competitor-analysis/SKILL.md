# 竞品分析（competitor-analysis）

> 竞品对标研究的结构模板。先读 deep-research 底座流程，本文件定义分析维度与信号清单。

## 分析框架

### 1. 竞品名单确认
先和用户确认对标谁：直接竞品（同品类同价格带）/ 间接竞品（替代场景）/ 标杆（跨品类学习对象）。
用户没说就先搜一版候选名单请用户圈定，别自作主张分析一堆。

### 2. 对比表（核心交付物）
列 = 竞品，行 = 维度，**每个单元格尽量注来源编号**。默认维度：
- 基本信息：成立时间、门店数/覆盖城市（或渠道）、价格带、目标客群；
- 产品：SKU 结构、招牌产品、上新节奏、近半年新品清单；
- 商业表现：营收/单店模型（有财报或可靠报道才填）、融资历史；
- 动向信号：近 3 个月新品、联名、营销动作、人事与组织变化。

### 3. SWOT
对本公司与主要竞品各出一版（或按用户要求）。每条要有事实支撑，
写不出事实支撑的格子宁可空着标"信息不足"，不凑数。

### 4. 差异化观察
总结 2-3 条"对手在做而没我们没做/做得弱"和"我们做得到而对手没做"的点，
每条给证据。

## 信号采集清单（差异化信息源）

- **招聘信息**：搜 `{竞品} 招聘`，新设岗位暴露战略方向（招"供应链总监"=自建供应链前兆）；
- **融资/工商**：`{竞品} 融资`、股东变更报道；
- **门店动态**：`{竞品} 新店 / 首店 / 城市`、`{竞品} 加盟`（加盟政策变化=扩张模式变化）；
- **产品信号**：`{竞品} 新品 / 联名 / 限定`，官方公众号/微博/新闻稿；
- **价格信号**：`{竞品} 涨价 / 降价 / 会员`。
- 软件/科技类竞品另加：GitHub star 曲线、版本发布节奏、招聘 JD 里的技术栈。

## 纪律

- 只用公开信息，报告里注明信息边界（"基于公开渠道，未含内部数据"）。
- 对比表缺失的格子写"未披露"，不估算不编造。
- 涉及未经证实的负面传闻：标注"传闻，单一来源"，不写成事实。
