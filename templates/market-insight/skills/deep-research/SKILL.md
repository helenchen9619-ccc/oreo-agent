# 深度研究流程（deep-research）

> 开放式研究问题的通用底座流程。澄清 → 拆解 → 多路搜索 → 带来源摘要 → 交叉验证 → 综合报告。

## 流程六步

### 1. 澄清追问
把用户的一句话需求变成可执行的研究问题。至少确认：研究对象、地理/时间范围、
结论用途（内部参考 / 决策支持 / 对外材料）、深度（30 分钟扫描 or 半天深研）。
问题清晰就直接开始，不要为了问而问。

### 2. 拆解子问题
把研究问题拆成 5-10 个可独立搜索的子问题，列成 checklist。例如
"现制酸奶行业值不值得加大投入" → 市场规模与增速 / 头部玩家与份额 / 价格带分布 /
消费场景与客群 / 上游供应链（奶源、菌种）/ 近一年融资与开店动态 / 风险（食安、同质化）。

### 3. 多路搜索
每个子问题设计 1-2 组关键词（中文为主，行业术语配英文），用 web_search 执行。
技巧：加年份限定新鲜度（"2026"）；加"报告/白皮书/研究院"找机构内容；
加 site 之外的来源词（"36氪"/"艾瑞"/"窄门餐眼"等行业垂直源）。

### 4. 带来源摘要（边搜边记）
每轮搜索后立刻把结果压缩成研究笔记：**摘要一句话 + URL + 发布日期 + 关键摘录（≤300 字）**。
摘要不够再 web_fetch 精读原文。绝不在上下文里堆整页正文——笔记就是报告的素材库。

### 5. 交叉验证
关键数字（市场规模、份额、增速）至少两个独立来源；来源冲突时并列呈现并分析差异原因
（口径/统计时间/机构立场）。只有单一来源的论断，在报告里标注"单一来源，待验证"。

### 6. 综合报告
产出 markdown 报告落工作区，结构：
- **执行摘要**：3-5 条结论，每条标置信度（高/中/低）；
- **正文**：按子问题组织，事实与推断分开；
- **来源附录**：编号 [1][2]…、标题、URL、日期、一句话摘录，正文用编号引用。

## 纪律

- **迭代上限**：搜索 2-6 轮。到 6 轮仍有空白，在报告"局限"一节如实说明，不无限搜下去。
- **压缩防膨胀**：任何时候上下文里只保留笔记式摘要，不保留整页原文。
- **时效标注**：趋势性结论必须说明依据的时间窗；超过 18 个月的来源标"旧闻，谨慎引用"。
- 查不到的内容写进报告"未覆盖/待人工深挖"清单，并建议替代路径
  （商业数据库、行业报告采购、专家访谈）。
