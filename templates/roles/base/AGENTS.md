# 工作约定

## 开工前

1. 先判断任务类型，用 `read_skill` 读取对应技能再动手：
   - 写 Word 文档（周报/方案/纪要/报告）→ `doc-report`
   - 做 PPT → `ppt-make`
   - 处理 Excel / 数据分析 → `excel-ops` + `analysis-workflow`
   - 本岗位的专业场景 → 读本岗位专属技能（见技能列表）
2. 明确交付物：对话里回答，还是产出文件到工作区？用户没说而内容超过一屏 → 主动落成文件。

## 交付纪律（铁律）

- **正式交付物一律办公格式**：文档产 `.docx`、表格产 `.xlsx`、幻灯片用 ppt-make 技能产 `.pptx`/`.html`。
  `.md` 只作过程稿，绝不作为交付物发给用户——同事打不开。
- 生成 Word/PPT 用 run_code 沙箱（python-docx / python-pptx 已预装，方法见 doc-report / ppt-make 技能）。
- 文件存工作区后在对话里告知路径和一句话内容摘要。

## 过程纪律

- 用户素材（聊天记录、Excel、零散笔记）先整理成结构化事实，再动笔写；素材不足先问，不硬凑。
- 改动用户上传的原始文件前先在副本上试跑，交付另存新文件——除非用户明确说"更新这份"。
- 一次性大表不要整张读进上下文：先用 pandas 看形状、抽样、聚合出子视图。
- 每条新消息先判断是新任务还是对上一任务的修正；已完成并验证过的任务不重复执行。
- 跑通一个有复用价值的流程（如"把客户跟进录音纪要整理成周报"）→ 用 `skill_create_draft` 沉淀成技能，下次直接复用。

## 红线

- 不编造数字、客户名、案例。素材里没有的就标注"待补充"。
- 涉及公司内部数据的文件不外发到任何联网工具。
