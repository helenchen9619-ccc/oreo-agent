# 营运优化口径与推算模板（metrics-ops-optimization）

> ⚠️ **口径为业内通用定义草稿，待业务方确认后修订。** 本文件是营运优化推算的唯一口径来源：
> 销量占比、BOM 展开、规格换算、强配单取整都以本文件为准。用户口径与本文件不一致时，
> 指出差异并按用户口径执行。

## 1. 新品销量占比 → 绝对量（锚定）

**口径（草稿）**：
- 销量占比 = 新品销量 ÷ 分母销量。**分母必须先问清**：全品类还是同品类？含不含套餐折算？
- 统计窗默认取上市后完整 N 天（N 由业务定，避开上市首日的尝鲜尖峰）；
- 绝对量锚定：新品预估门店销量 = 占比 × 该门店**同窗口分母销量**（不是占比 × 平均销量，
  店与店体量差异大，按店锚定）。

**要点**：
- 占比是比例不是量，**离开分母和锚定方式的占比没有意义**，拿到占比先问这两样；
- 给出门店级推算时，同时给全部门店汇总量，方便和采购侧总量对账。

## 2. BOM 展开（成品 → 原物料）

**口径**：单杯/单份用量 × 门店销量 = 原物料需求量。一级展开用 merge 即可：

```python
# sales: 门店, 产品, 销量；bom: 产品, 原物料编码, 单份用量, 用量单位
need = sales.merge(bom, on="产品", how="left")
need["需求量"] = need["销量"] * need["单份用量"]
# how="left" 后立即检查：BOM 缺失的产品（原物料编码为 NaN）必须列出来问业务方，不能悄悄丢掉
missing = need[need["原物料编码"].isna()]["产品"].unique()
```

**要点**：
- 多层 BOM（半成品→原料）逐层展开，每层重复上述 merge+缺漏检查；
- **BOM 缺漏是第一优先级问题**：销量表里有、BOM 里没有的产品单独列清单，宁可中断问业务方
  也不按 0 用量继续算；
- 损耗率/出成率显式参数化：`实际需求量 = 理论需求量 ÷ (1 - 损耗率)`，损耗率作为输入参数
  标注在计算过程里，不写死在代码里。

## 3. 规格换算（用量单位 → 采购单位）

**纪律（红线）**：BOM 用量单位（克/杯）与采购规格单位（公斤/箱、包/件）之间的换算，
**必须先输出换算映射表给用户确认**，确认后才进入计算。禁止静默换算。

换算映射表至少包含：原物料编码、名称、用量单位、采购单位、换算系数、系数来源（规格表/用户口头）。

```python
# spec: 原物料编码, 采购单位, 每采购单位含量(用量单位)
merged = need.merge(spec, on="原物料编码", how="left")
merged["采购量_raw"] = merged["需求量"] / merged["每采购单位含量"]
```

**要点**：换算系数来源必须留痕；规格表缺换算系数的原物料同样列清单问业务方。

## 4. 强配单生成（取整 + 留痕）

**口径（草稿）**：
- 按包装规格/MOQ **向上取整**（`math.ceil`），强配宁多勿缺——但要在计算过程里给出
  取整前理论值，让业务方看到多配了多少；
- 同一门店同一原物料多产品共用的，先汇总再取整（不要按产品分别取整再加总，会虚高）。

```python
import math
merged["强配量"] = merged["采购量_raw"].apply(math.ceil)  # 以采购单位为粒度
```

**输出规范（强配单 = 执行单据，按单据标准交付）**：
- Excel 至少两个 sheet：**强配单明细**（门店 × 原物料 × 强配量，业务直接可用）+
  **计算过程**（销量占比口径、锚定方式、损耗率、换算系数、取整前理论值，可复算留痕）；
- 交付前必过 excel-ops 技能的 `scripts/recalc_check.py` 重算校验；
- 文件名带日期与批次（如 `强配单_2026-08-17_新品X.xlsx`），落工作区，不覆盖历史批次
  （除非用户明确要覆盖）。

## 通用提醒

- 推算链路上每一步留中间表（占比锚定表、BOM 展开表、换算表、取整表），
  业务方挑数时能逐级倒推；
- 门店清单以业务方提供的为准：新店/闭店清单不参与推算的，先剔除再算，并在计算过程里注明；
- 所有"率"和"系数"同时给出绝对值与来源。
