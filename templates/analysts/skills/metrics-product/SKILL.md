# 产品指标口径与计算模板（metrics-product）

> ⚠️ **口径为业内通用定义草稿，待业务方确认后修订。** 本文件是产品指标的唯一口径来源：
> 计算任何产品指标时以本文件定义为准。用户口径与本文件不一致时，指出差异并按用户口径执行。

## 1. 北极星指标与指标体系

**方法**：北极星指标 = 唯一最能代表产品长期价值的指标（如内容产品的"周消费时长"、工具产品的"周完成任务数"）。
**搭建步骤**：
1. 和业务方确认北极星指标及其口径（这是共识工程，不是计算问题）；
2. 向下拆一级驱动指标（输入型，可被团队动作直接影响），形成「北极星 = f(一级指标)」的乘法/加法关系；
3. 每个指标登记：定义、分子分母、数据源、负责人、更新频率。
**要点**：一级指标必须**可行动**——"提升留存"不是输入指标，"新用户次日完成核心动作率"才是。

## 2. A/B 检验

**流程**：
1. 实验前先定：主指标、预期提升幅度（MDE）、显著性水平（α=0.05）、功效（80%）→ 估算所需样本量；
2. 实验中不看结果（peeking 会放大假阳性）；
3. 结束后做检验：

```python
from scipy import stats  # 沙箱无 scipy 时用 statsmodels 或手写正态近似

# 比率指标（转化率等）：两比例 z 检验
import numpy as np

def two_prop_ztest(x1, n1, x2, n2):
    p1, p2 = x1 / n1, x2 / n2
    p_pool = (x1 + x2) / (n1 + n2)
    se = np.sqrt(p_pool * (1 - p_pool) * (1 / n1 + 1 / n2))
    z = (p2 - p1) / se
    from math import erf
    p_value = 2 * (1 - 0.5 * (1 + erf(abs(z) / np.sqrt(2))))
    return p2 - p1, p_value
```

**纪律**：
- **样本量不足就说不能下结论**，给出"按当前流量还需 X 天"的估算，不迎合想要的答案；
- 报告必须带：绝对差值、相对提升、p 值、置信区间；
- 多个指标同时看要提醒多重检验问题（看 20 个指标必有 1 个"显著"）。

## 3. 功能渗透率

**口径（草稿）**：功能渗透率 = 统计窗口内使用过该功能的去重用户数 ÷ 窗口内活跃去重用户数。
**要点**：
- 必须拆新老用户：新功能渗透率被存量未触达用户稀释是最常见误读；正确做法是只看「功能曝光用户」的渗透（渗透率 = 使用 ÷ 曝光）；
- 配合留存看：用过功能的用户次周留存 vs 没用过的——但注意这是相关不是因果，下结论要说明。

```python
exposed = df[df["事件"] == "功能曝光"]["用户ID"].unique()
used = df[df["事件"] == "功能使用"]["用户ID"].unique()
adoption = len(set(used) & set(exposed)) / len(exposed)
```

## 4. 指标异动归因

指标异动（如日活跌 10%）的标准排查顺序：
1. **先查数据本身**：埋点变更、上报延迟、版本发布——约一半"异动"是数据问题；
2. **拆维度定位**：平台/版本/渠道/地区/新老用户，找到异动集中的切片；
3. **对时间**：异动起点对齐发布记录/运营动作/外部事件；
4. 给出归因假设列表并标注每条的确信度，而非单一口头结论。

## 通用提醒

- 所有比率指标同时给出分子分母绝对值。
- "活跃用户"必须先定义（打开 App？完成核心动作？），不同定义的 DAU 不可比。
