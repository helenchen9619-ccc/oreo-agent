# 五步分析法（analysis-workflow）

任何数据分析请求都按这五步走。步骤可以轻量，但**不能跳过**。

## 第 1 步：澄清口径（先问，再算）

动手前确认四件事，缺就主动问；用户答不上来就给出你采用的默认口径并明确标注：

1. **业务问题**：这个数要支持什么决策？（决定分析深度和呈现方式）
2. **指标口径**：分子分母是什么？（涉及部门指标时，以本部门 metrics 技能文件为准）
3. **数据范围**：时间段、业务范围（含不含退货/测试单/内部单）、粒度（按天/周/月，按 SKU/仓库/渠道）。
4. **对比基准**：环比？同比？目标值？没有基准的数字没有意义的判断。

## 第 2 步：数据质量检查

数据到手先体检，发现硬伤**先报告再继续**：

```python
df.shape                      # 行数列数符合预期吗
df.isna().sum()               # 缺失在哪列、缺多少
df.duplicated().sum()         # 重复行
df.describe()                 # 异常值（负库存？超界日期？）
df["日期"].min(), df["日期"].max()  # 时间范围覆盖了吗
```

常见硬伤：单位不一致（元 vs 万元）、口径混排（含税/不含税）、导出截断（Excel 104 万行上限）、
表头错位、隐藏行。检查结论一句话告诉用户："数据 X 行，时间覆盖 A 到 B，发现 Y 个缺失已剔除"。

## 第 3 步：探索与下钻

- 先看大盘，再拆维度（渠道/客群/区域/时间段），**平均数掩盖一切，分布和分组才出洞察**。
- 异常点要下钻到明细行确认是数据问题还是真实业务事件。
- 一次只验证一个假设；每个中间结论能对应到具体的查询/代码。

## 第 4 步：可视化

- 图表服务结论，不是装饰：趋势用折线、对比用柱状、占比用条形/饼（>5 类用条形）、分布用直方图。
- 标题写结论（"3 月周转率环比下降 12%"），坐标轴带单位，中文标注。
- 一张图只说一件事。

## 第 5 步：管理层报告

输出结构（按详略需要裁剪）：

1. **结论摘要**（≤3 条，每条一句话+一个关键数字）
2. **关键发现**（数据支撑，带图表/表格）
3. **行动建议**（每条建议对应一个发现，标注预期影响和置信度）
4. **附录**：口径说明、数据范围、代码/文件留档位置

## 纪律

- 迭代有上限：一个方向深挖不超过 3 轮没有增量就换方向，并向用户说明。
- 中间过程文件和最终交付物都留在工作区，回答里给出文件名。
